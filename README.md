# Переплёт

Читалка совместной книги. Главы — это markdown-файлы, приложение собирает из них обложку, оглавление и экран чтения. Сервера нет: сайт статический, открывается по ссылке.

## Запуск

```text
npm i
npm run dev
```

Сборка и проверка:

```text
npm test
npm run lint
npm run format:check
npm run build
npm run preview
```

`npm run build` сначала проверяет типы (`tsc -b`), потом собирает `dist`.

## Как устроены главы

Файлы лежат в `src/content/chapters` и подхватываются сами через `import.meta.glob` в режиме `eager`. Регистрировать главу в коде не нужно: добавили файл — она появилась в оглавлении.

`eager`, а не ленивая загрузка, потому что книга короткая, а обложке и оглавлению все заголовки нужны сразу, без отдельного состояния «загружаем». Когда глав станет много, этот же glob можно переключить на ленивый.

Подробности — в [docs/ADDING_A_CHAPTER.md](docs/ADDING_A_CHAPTER.md).

## Шрифты

Текст книги — [Literata](https://fonts.google.com/specimen/Literata): современная антиква, нарисованная для долгого чтения на экране, с полной кириллицей и настоящим курсивом. EB Garamond на телефоне слишком тонкая, Lora мягче и меньше похожа на книжный набор. Интерфейс — Manrope: нейтральный гротеск с кириллицей, он не спорит с антиквой. Заголовки самой книги тоже на Literata, потому что это голос текста, а не кнопки.

Оба шрифта подключены через `@fontsource` с `unicode-range`, так что кириллица и латиница (включая тире и многоточие) идут из этих файлов, а не из запасного шрифта системы.

Типографика (неразрывные пробелы после коротких слов и предлогов, ёлочки вместо прямых кавычек) делается при отрисовке. Исходный markdown не правится.

## Деплой

Сборка — папка `dist`. В `vite.config.ts` уже стоит `base: './'`, поэтому относительные пути к скриптам и картинкам работают и на корне домена, и в подкаталоге. Роутер хэш-овый (`#/read/...`), правила редиректов на хостинге не нужны.

### Cloudflare Pages

1. Подключить репозиторий.
2. Build command: `npm run build`.
3. Output directory: `dist`.
4. Node.js 22.

### Netlify

1. Build command: `npm run build`.
2. Publish directory: `dist`.

### GitHub Pages

1. В настройках репозитория включить Pages из GitHub Actions или из ветки, куда выкладывается `dist`.
2. Для проекта по адресу `https://<user>.github.io/<repo>/` текущий `base: './'` уже подходит: ассеты относительные, хэш-роутер не зависит от каталога.
3. Если сайт откроется с корня домена, `base` можно сменить на `'/'`.

После деплоя превью ссылки в мессенджере берёт название и описание из `index.html`. Картинка — `og.svg`. У части мессенджеров она появится только по абсолютному адресу: если превью пустое, пропишите в `og:image` полный URL уже задеплоенного файла.

## На телефон

Сайт ставится как приложение (PWA). Нужен уже задеплоенный адрес по HTTPS: с `npm run dev` установка не предлагается, сервис-воркер появляется только после `npm run build`.

- Android, Chrome: открыть ссылку → меню → «Установить приложение» или «Добавить на главный экран».
- iPhone, Safari: «Поделиться» → «На экран „Домой“».

Дальше книга открывается со значка и читается без сети. Новая глава скачается, когда приложение откроют при включённом интернете: воркер обновит кэш и перезагрузит страницу.
